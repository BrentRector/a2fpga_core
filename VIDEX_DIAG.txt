ADDRESS REFERENCE:
- 49328 ($C0B0) = CRTC address reg / Bank 0 select
- 49329 ($C0B1) = CRTC data reg
- 49332 ($C0B4) = Bank 1 select
- 49336 ($C0B8) = Bank 2 select
- 49340 ($C0BC) = Bank 3 select
- 49664 ($C200) = Slot 2 ROM (SSC)
- 49920 ($C300) = Slot 3 ROM (Videx)
- 50176 ($C400) = Slot 4 ROM
- 51200 ($C800) = Expansion ROM
- 52224 ($CC00) = VRAM window start
- 52672 ($CDC0) = VRAM window + $1C0
- 52673 ($CDC1) = VRAM window + $1C1
- 53247 ($CFFF) = Expansion ROM disable

NOTES:
- Line 5: Initializes all 4 VRAM banks to spaces (32/$20) before tests.
- T01: Even address ($C0B0) read = status register. MC6845 Type 0
  has no status, so should return 0.
- T02/T03: R14/R15 are readable. Values depend on cursor position.
- T04-T06: Tests that card drives the bus for "write-only" registers.
  HD6845SP Type 1 returns written values for all R0-R15.
  Test checks value != 192 ($C0 = open bus). Any other value = OK.
- T07: Slot 3 ROM byte at $C300 should be $2C (44).
- T08: Expansion ROM byte at $C800 should be $AD (173).
- T09-T10: VRAM write/read at $CDC0/$CDC1, bank 3.
- T11: $CFFF clears expansion ROM ownership, $C300 re-enters,
  $C800 should return Videx ROM again.
- T12: After CFFF+reenter cycle, VRAM data from T09 should survive.
  Re-selects bank 3 before reading.
- T13: Full R14/R15 write + read-back verification.
- T14: 4-bank switch isolation. Writes distinct patterns ($AA, $33,
  $CC, $55) to all 4 banks at $CDC0, verifies banks 0 and 3
  retained their values. Bank addresses: $C0B0(0), $C0B4(1),
  $C0B8(2), $C0BC(3).
- T15: Sequential VRAM fill/verify (256 bytes starting at $CC00, bank 3).
- T16: VRAM stress test (write+immediate read, 50 iterations x 256 bytes).
  Tests for VRAM read pipeline collisions with the video scanner.
- T17: Register isolation diagnostic. Writes 85 to R14, then selects R0
  and reads data register. Three outcomes: 85=FAIL:LEAK (R14 value leaked
  through index switch), 192=FAIL:OPEN BUS (no card responding),
  any other value=OK(REG) (card correctly returns R0's own value).
- T18: Slot deselection test. Accesses $C200 (slot 2) which should cause
  Videx to release C8 ownership. Then reads $C800 — Videx should NOT
  respond. Re-enters $C300, verifies $C800 returns Videx ROM again.
  SSC uses SLOTROM guard (checks SLOTROM==2 at read time). Videx uses
  self-clearing c8_owned (clears on other-slot $Csxx access).
- T19: $CFFF ownership clearing WITHOUT immediate re-entry. Unlike T11
  which clears and immediately re-enters, this verifies the intermediate
  state: after $CFFF, $C800 must NOT return Videx ROM (rom_ownership=0).
- T20: VRAM isolation across slot switch. Writes to VRAM on bank 3,
  switches to slot 2, verifies VRAM is NOT readable (rom_c8_active=0
  blocks VRAM window), switches back, verifies VRAM data survived.
- T21: Multi-slot scan simulation (like Pascal device scanning). Accesses
  slot 3, then slot 2, then slot 4, then back to slot 3. Verifies both
  ROM and VRAM are accessible after the round trip.

IF CRASH AT SPECIFIC TEST:
- T01-T06: CRTC read logic issue
- T07: Slot ROM / io_select_n issue
- T08: Expansion ROM / rom_ownership issue
- T09-T10: VRAM write or read pipeline issue
- T11-T12: $CFFF / rom_ownership clearing/re-entering issue
- T13: CRTC write/read-back issue
- T14: Bank selection side-effect issue
- T15-T16: VRAM timing / scanner collision issue
- T17: CRTC register read-back leak
- T18: SLOTROM guard missing — Videx responds to C8 reads when
  another slot is active
- T19: rom_ownership not clearing on $CFFF, or re-entry not working
- T20: VRAM accessible when it shouldn't be (rom_c8_active not gating
  VRAM window), or VRAM data lost during slot switch
- T21: ROM/VRAM not surviving a multi-slot round trip (Pascal scan issue)
